# Picolah 用户画像与短视频推荐 v1

## 范围与依据

本实现参考用户提供的[抖音推流算法介绍](https://blog.csdn.net/geniusChinaHN/article/details/149667180)中“行为反馈、兴趣标签、内容匹配、探索”的思路，并对照 [TikTok 官方推荐说明](https://www.tiktok.com/safety/en/making-your-feed-for-you)。它是本项目的可解释启发式推荐，不是抖音未公开算法的复刻，也没有假设文章中的流量池阈值或权重是官方事实。

推荐接口、行为落库、画像和账号合并均实际运行。当前内容池仍是 5 张演示短视频卡片，不包含真实视频文件；卡片有效停留时间用于演示反馈闭环。`videoUrl` 可接入真实媒体，前端只在媒体实际播放且页面可见时计时。此功能是站内信息流推荐，不是系统通知推送，也不涉及自动爬虫或付费 API。

## 数据流与入口

1. `web/shared/reels.ts` 是服务端可信的内容目录：商品、品类、品牌、主题、作者、市场、发布时间、时长。客户端不能上报自定义标签或分数。
2. Reels 页面通过 `GET /api/reels?market=SG&limit=5&exclude=id1,id2` 获取个性化队列和推荐原因；正在看的卡片保持稳定，更新后续队列。
3. `POST /api/reels/events` 接受观看与互动事件，成功返回 `204`。非法内容/字段返回 `400`，冲突重放返回 `409`。
4. `GET /api/profile` 的 `video` 字段展示观看次数、有效时长、完播率、快速划走、点赞收藏和品类/品牌/主题/作者偏好。
5. 购物画像页“清空画像”通过 `DELETE /api/profile` 清空购物和视频行为，恢复推荐冷启动；账号删除也清理关联数据。

请求示例（沿用项目 cookie 或匿名 `X-Picolah-User` 身份）：

```json
{
  "eventId": "unique-event-0001",
  "sessionId": "view-session-0001",
  "reelId": "xm5-six-markets",
  "type": "watch",
  "market": "SG",
  "watchMs": 8000,
  "ended": false
}
```

`watchMs` 是同一观看会话的累计有效毫秒，不是增量；改变快照需要新 `eventId`，重试相同事件沿用原 ID。`ended` 仅表示本次观看结束（划走、完成或离页），暂停/后台心跳不算结束。时长不能超过目录时长。

## 信号与排序

`web/server/reels-ranking.ts` 中的初始权重供后续实验调整，不代表机器学习训练结果：

| 信号 | 兴趣贡献 |
| --- | --- |
| 观看 | 时长比例 × 1.2；观看 ≥90% 再加 1.8 |
| 快速划走 | 结束时观看 <15%，贡献 −2 |
| 点赞 / 收藏 / 关注 / 分享 / 查看比价 | 3.5 / 4.5 / 4 / 2 / 5 |
| 不感兴趣 | −7，且直接排除该视频 |
| 商品比价 / 商家点击 | 1.6 / 2.3，补充购物品类、品牌、商品偏好 |

所有兴趣按 `0.65 × 2^(−天数/7) + 0.35 × 2^(−天数/30)` 衰减，兼顾近期和长期兴趣。取消点赞、收藏、关注后撤销对应状态贡献。关注按作者生效，不按单条视频重复累计。

候选得分由品类/品牌/商品/作者/主题匹配、关注、真实观众反馈、内容新鲜度和较弱的市场相关性组成；近期已看内容降权。真实观众反馈按用户去重，用 10 个中性先验观众平滑小样本，禁止使用演示点赞数作为质量证据。最终队列对重复作者、品类和品牌降权；第 4 位在有合适未看候选时保留探索内容。

新用户使用购物信号（如有）、市场、新鲜度和真实反馈启动；无行为时不伪造画像。内容全部标为不感兴趣时返回空队列，不绕过排除规则。返回“观看和购物兴趣 / 关注作者 / 近期反馈 / 新兴趣探索”等双语原因。

## 一致性与隐私边界

- SQLite/PostgreSQL 均保存 `reel_sessions`、`reel_events`、`reel_event_receipts`；观看状态按用户与会话唯一，累计时长取 MAX，结束状态只前进。
- `eventId` 在用户范围内幂等；同一会话不能改变视频。页面 StrictMode 探测不创建假观看，暂停/隐藏不增加时长，失败互动不假装保存成功。
- 已登录请求优先使用服务端账号身份，匿名画像在登录时合并；同名会话/事件冲突会映射新 ID，避免覆盖另一设备记录。
- 匿名浏览器 ID 是沿用项目的便利标识，不是强认证；生产环境应开启认证、增加行为限流/异常检测，不能将客户端观看时长当作防作弊凭证。
- 不采集年龄、性别、联系人或其他敏感推断信息。画像可查看和重置，隐私说明同步披露服务端保存。

## 验证

```sh
pnpm --filter @picolah/web typecheck
pnpm --filter @picolah/web test
pnpm --dir web exec tsx --test src/lib/reel-clock.test.ts
pnpm --filter @picolah/web build
```

可选浏览器回归：先启动前端，再运行 `REELS_TEST_URL=http://127.0.0.1:5173 pnpm --dir web exec tsx --test src/lib/reel-playback.browser.test.ts`。该测试拦截 API，在独立浏览器上下文验证播放/暂停/隐藏、反馈失败与重试，不写入本地真实账号数据。

服务端测试覆盖幂等与乱序快照、并发写入、完播/快速划走、撤销互动、不同用户不同排序、排除/空队列、清空画像、登录合并、账号身份优先，以及 SQLite 和 PostgreSQL 一致性。

## 后续生产化

扩大内容库时，应将目录移到内容管理表并接入真实视频、审核与版权流程；将全量候选/反馈读取改成分页召回和预聚合特征。当前 5 条内容无法验证大规模效果，不应据此承诺提升留存。上线前需要真实样本的完播、有效停留、负反馈、品类覆盖率监测和 A/B 实验，并增加行为数据保留清理策略及反作弊限流。
